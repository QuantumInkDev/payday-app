# Repo Restructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the three Windows projects into `apps/windows/` so the repo can hold the other apps, with no behaviour change and a repeatable way to build and test Windows from this Mac.

**Architecture:** `git mv` the three .NET projects as a unit (their `..\PayDay.Core` references stay valid because they move together). A small Mac-side script dispatches build + test to the arm64 Windows VM through `prlctl exec`, using its own build checkout on the VM so the user's daily clone is never touched. Docs that give paths or commands are updated in the same commit as the move.

**Tech Stack:** git, bash (macOS), Parallels `prlctl`, .NET 9 SDK on the VM (9.0.318), WinUI 3 / xUnit.

**Spec:** `planning/2026-11-14-multiplatform-design.md` §5 (layout) and §9 step 1. Read §3 for the VM facts.

## Global Constraints

- No behaviour change. Nothing under `PayDay/`, `PayDay.Core/`, `PayDay.Tests/` is edited, only moved.
- Windows build **0 warnings / 0 errors**, tests **194/194**, verified on the arm64 VM.
- History preserved: `git log --follow` on a moved file must show its pre-move commits.
- Target layout now: `apps/windows/PayDay/`, `apps/windows/PayDay.Core/`, `apps/windows/PayDay.Tests/`. `tools/` and `planning/` stay at the root. Do **not** create `apps/apple`, `apps/android`, `apps/web`, `spec/` or `design/` yet; the steps that fill them create them (git can't hold empty folders anyway).
- The code keeps the PayDay name internally. Product name in prose is **FutureCheck**.
- Never touch the user's VM clone `C:\Projects\PayDayApp`. VM builds use `C:\Builds\payday-app`.
- VM name: `Win 11 Arm Dev`. Commands there run as `NT AUTHORITY\SYSTEM`; `dotnet` is at `C:\Program Files\dotnet\dotnet.exe` (not on PATH); git is on PATH. `prlctl exec` returns the guest's exit code (verified).
- The GitHub repo `QuantumInkDev/payday-app` is **public**, so the VM can clone/fetch without credentials.
- Commit format: `Session 2026-11-14: <summary>`, bullet body, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. One commit per task.
- Historical planning docs (`planning/PAYDAY_WINUI3_PLAN.md`, `planning/sprint-0*.md`, `planning/current-sprint.md`) are records; don't rewrite their paths.

## Review Focus

1. **Installed app loses its data.** If the move changed the package identity, the installed app's `LocalState\payday.db` would sit under the old package family and the rebuilt app would open empty. Expect `Package.appxmanifest` byte-identical after the move. Pinned in Task 3 Step 5 (every moved file must be an `R100` rename).
2. **Ghost folders after the move.** `git mv` moves only tracked files; ignored `bin/`/`obj/` stay behind in root `PayDay*/` folders and confuse IDEs and Serena. Expect no root `PayDay*` folders afterwards. Pinned in Task 3 Step 3; rig/VM clone cleanup is written into `SESSION_STATUS.md` (Task 3 Step 9).
3. **VM builds an old commit.** The VM fetches from GitHub, so an unpushed local commit would silently build whatever was last pushed. Expect the script to refuse with a clear message. Pinned in Task 2 Step 3.
4. **Icon tool writes to the old path.** `tools/render-app-icon.ps1` defaults `AssetsDir` to `..\PayDay\Assets`; after the move it would create a stray folder. Expect it to point at `..\apps\windows\PayDay\Assets`. Pinned in Task 3 Step 4.
5. **Docs send someone to dead paths.** Build commands in `CLAUDE.md` and Serena memories would fail after the move. Expect every command in them to work from the repo root. Pinned in Task 3 Step 6.

### Task 2: VM build script, with a baseline on the current layout

**Files:**
- Create: `tools/vm-build.sh` (executable)

**Interfaces:**
- Produces: `tools/vm-build.sh [git-ref]` — builds the app and runs the tests on the VM at that commit (default `HEAD`). Exit 0 on success; the guest's exit code on build/test failure; 2 when the commit isn't on GitHub. Env overrides: `FC_VM` (default `Win 11 Arm Dev`), `FC_VM_DIR` (default `C:\Builds\payday-app`).

- [ ] **Step 1: Write `tools/vm-build.sh`**

Behaviour, in order:
1. `set -euo pipefail`; resolve `SHA=$(git rev-parse "${1:-HEAD}^{commit}")`.
2. `git fetch --quiet origin`; if `git branch -r --contains "$SHA"` is empty, print `Commit <short sha> is not on GitHub yet. Push it first (git push), then re-run.` to stderr and exit 2.
3. Pick the project root from the commit itself: if `git cat-file -e "$SHA:apps/windows/PayDay/PayDay.csproj"` succeeds, `ROOT='apps\windows'`, otherwise `ROOT='.'`.
4. Run in the guest via `prlctl exec "$FC_VM" cmd /c "<commands joined with &&>"`:
   - `if not exist <DIR>\.git git clone --quiet https://github.com/QuantumInkDev/payday-app.git <DIR>`
   - `git -C <DIR> fetch --quiet origin`
   - `git -C <DIR> checkout --quiet --force --detach <SHA>`
   - `git -C <DIR> clean -fdxq`
   - `"C:\Program Files\dotnet\dotnet.exe" build <DIR>\<ROOT>\PayDay\PayDay.csproj -nologo -p:TreatWarningsAsErrors=true`
   - `"C:\Program Files\dotnet\dotnet.exe" test <DIR>\<ROOT>\PayDay.Tests -nologo -p:TreatWarningsAsErrors=true`
5. Propagate the `prlctl` exit code; on success print `VM build OK at <short sha> (<ROOT>)`.

Then `chmod +x tools/vm-build.sh`.

- [ ] **Step 2: Baseline run on the current (pre-move) layout**

Commit the script first so it is on GitHub:
```bash
git add tools/vm-build.sh
git commit -m "Session 2026-11-14: add VM build script" -m "- tools/vm-build.sh builds and tests the Windows app on the arm64 VM via prlctl" -m "- Uses its own checkout at C:\Builds\payday-app; never touches the daily clone" -m "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"
git push
tools/vm-build.sh
```
Expected: build output ends `0 Warning(s)` / `0 Error(s)`; test output shows `Passed!  - Failed:     0, Passed:   194`; last line `VM build OK at <sha> (.)`; exit 0.
If the WinUI build fails under SYSTEM (something the 2026-09-09 interactive build didn't hit), stop and report the error — don't work around it in the app project.

- [ ] **Step 3: Unpushed-commit guard**
